# 浪尖雷达 · 收波 — Breaker Delta Echo Catcher

[English](README.md) · **中文**

浪尖雷达 / Breaker Delta 的浏览器扩展（Chrome 先行，版本 0.6.0）。
它陪你刷网页：看到可能要火的东西，一键先存下来；打开已经被雷达
收录的页面时，它会告诉你这个话题的浪高。

> 隐私一句话版：只在你主动点击时读取当前页，不收集浏览历史，
> 所有数据只存在你自己的浏览器里。详见下方「隐私声明」。

## 它能做什么

| 功能 | 说明 |
|---|---|
| 🌀 一键收波 | 在任何页面点扩展图标，把当前页标题、链接、你选中的文字和一句话理由存进本地回波箱 |
| ✓ 收录状态 | 弹窗顶部会直接告诉你：当前页的话题是否已被雷达收录、浪高多少、首次出现于哪天 |
| 🌊 浪高徽章 | 在 GitHub / Hacker News / Reddit / X / Product Hunt 五个站点，打开已收录话题的页面时，右下角出现徽章条（话题名、浪高、首现日期、话题页链接）；正在破圈的话题还会带 ⚡ 标记 |
| ⚡ 破圈角标 | 扩展图标上的橙色数字 = 当前正在破圈（共振/突涨）的提醒条数 |
| 🚀 一键投波 | 在每条回波旁点「投波」（或用「逐条投波」投全部），会直接在数据仓打开一个预填好的 GitHub Issue 页：标题、正文、标签都自动填好，你只需点 Submit。不需要任何令牌 |
| ⚙ 设置页 | 可改投波目标数据仓、实例站点地址、收波后是否立即投波、投波后是否保留本地副本 |
| 📤 导出投波 | 把回波箱一键复制成 GitHub Issue 格式文本，或下载成 JSON 文件 |

## 安装（开发者模式侧载）

扩展暂未上架 Chrome 应用商店，用「加载已解压的扩展程序」安装。

**方式 A：用现成的侧载副本（最快）**

`~/workspace/breaker-delta-extension/` 是预先构建好的副本（构建产物 +
线上数据快照都已就位），直接跳到下面的第 2 步选这个目录即可。

**方式 B：从源码构建**

```bash
# 在引擎仓 daiyanze/breaker-delta 根目录
npm run build -w @breaker-delta/extension
```

产物在 `apps/extension/dist/`。注意：话题/提醒数据（`data/topics.json`、
`data/alerts.json`）是实例数据、不存放在代码仓里，构建后需要从一次站点
构建产物或已发布站点复制进 `dist/data/`，方法见 `data/README.md`；
方式 A 的副本已经带好快照，不用做这一步。

**加载步骤**

1. 打开 `chrome://extensions/`
2. 打开右上角「开发者模式」
3. 点「加载已解压的扩展程序」，选择构建产物目录（方式 B 是
   `apps/extension/dist/`，方式 A 是侧载副本目录）
4. 工具栏出现浪尖雷达图标即成功；图标上的橙色角标数字是当前数据
   快照里的破圈提醒条数（没有提醒时不显示数字）

建议把扩展固定（pin）到工具栏，收波时少点一次菜单。

## 使用说明

### 收波

1. 在任何页面上，（可选）先用鼠标选中一段你觉得关键的文字
2. 点工具栏的扩展图标——弹窗会显示当前页标题和链接；如果有选中
   文本，会提示「已选中 N 字，收波时会一并保存摘录」
3. （可选）填一句话理由：为什么觉得这是个回波
4. 点「🌀 收下这个回波」

弹窗顶部还会顺带告诉你这个页面是否已被雷达收录：已收录会显示
话题名、浪高和首现日期，并可点「查看话题」跳到站点上的话题页；
未收录则提示你可以先收波观察。

### 回波箱

弹窗下半部分是本地回波箱，新的在最上面。每条回波显示标题、链接、
你的理由和选中文本摘录（鼠标悬停可看全文），点标题或链接可在新
标签页打开原页面，不想要的可以逐条删除。

### 投波（一键直达 GitHub Issue）

每条回波旁都有一个「🌀 投波」按钮：点它会在数据仓打开新建 Issue
页，用的是数据仓的 `echo.md` 模板，这条回波的标题、链接、理由和
摘录已经通过 GitHub 官方的预填参数自动填进输入框，你检查一眼点
Submit 就提交成功——扩展不会替你提交，也不需要任何令牌。
「🌀 逐条投波」会对所有还没投过的回波逐条打开这样的页面。

打开投波页后，这条回波会被标上「已打开投波页」（或按设置直接
删除本地副本）。注意扩展看不到你最后有没有在 GitHub 点 Submit，
所以这个标记只表示「页面打开过」，不表示「已提交」。

前提：你已登录 GitHub 且对目标仓有开 Issue 的权限。摘录特别长时
会自动截断，保证预填链接不超出 GitHub 的长度上限。

### 导出投波

- **📋 导出投波**：把回波箱全部内容复制成 GitHub Issue 格式文本，
  去数据仓 `breaker-delta-data` 新建 Issue 粘贴提交，回波就会进入
  雷达的扫描流程
- **⬇ 下载 JSON**：把全部回波下载成 `breaker-delta-echoes.json` 存档

### 设置页

弹窗页脚点「⚙ 设置」（或在扩展详情页打开「扩展程序选项」）：
可改**数据仓**（投波目标，默认 `daiyanze/breaker-delta-data`，
也接受完整的 github.com 地址）、**实例站点地址**（话题页链接和
话题/破圈数据的来源，自建实例的人改成自己的）、**收波后立即
打开投波页**、**投波后保留本地副本**。设置只存在浏览器本地。
设置页还能看到当前缓存的数据量和拉取时间，并可手动刷新数据。

### 浪高徽章

打开五个站点（GitHub、Hacker News、Reddit、X、Product Hunt）里与
已收录话题匹配的页面，右下角会出现徽章条。匹配依据是页面链接或
标题命中话题的链接模式/关键词。徽章可点 × 关闭（刷新页面会重新
出现）。不在这五个站点时不会有徽章，但收波在任何页面都能用。

## 数据从哪来、怎么更新

徽章和角标用的 `topics.json` / `alerts.json` 由浪尖雷达站点构建时
从每期数据自动生成，随站点发布在
`https://daiyanze.github.io/breaker-delta-data/data/` 下。0.6.0 起
扩展会**直接从设置里的实例站点拉取**这份数据（安装时、浏览器
启动时、打开弹窗时），并缓存在本地；拉不到或缓存为空时才用打包
时放进去的快照兜底。设置页里可以手动「立即刷新数据」。也可以
继续手动更新快照：把这两个文件的新版本覆盖进扩展目录的 `data/`
文件夹，然后在 `chrome://extensions/` 里点扩展卡片上的刷新按钮，
不用改代码。全程无后端、无账号。

## 权限说明（为什么只要这三个）

| 权限 | 用途 |
|---|---|
| `activeTab` | 只在你点击扩展图标时，临时获得当前标签页的访问权，用来读标题、链接和选中文本；平时扩展碰不到你的页面 |
| `scripting` | 配合 `activeTab`，在你点击收波时读取页面选中文本 |
| `storage` | 把回波箱存在浏览器本地 |

内容脚本（徽章）只在上述五个站点运行，由清单文件限定，不在其他
任何网站注入。扩展没有申请 `tabs`、`history`、`cookies`、
`<all_urls>` 等权限。扩展唯一的网络请求是：从设置里的实例站点
（默认官方实例）下载 `data/topics.json` / `data/alerts.json`，
以及你点「投波」时打开 GitHub Issue 页。

## 隐私声明

- **不收集浏览历史**：扩展不会记录你访问过哪些页面。内容脚本只在
  五个站点把当前页链接/标题与扩展自带的话题索引在本地比对，
  比对结果不离开浏览器
- **只响应主动操作**：收波只发生在你点击「收下这个回波」时，
  抓取范围只有当前页标题、链接、你选中的文本和你填的理由
- **数据只存本地**：回波箱存在你的浏览器本地，不自动上传任何
  服务器；导出完全由你手动触发，内容发到哪里由你决定
- **只下载不上传**：数据刷新只从你设置的实例站点下载公开的
  话题/破圈 JSON，不向任何地方发送数据
- **无遥测、无第三方脚本**：不含统计、广告或远程代码

## 常见问题与故障排查

**装好了，但图标上没有角标数字？**
正常：没有破圈提醒时角标就是空的。另外确认扩展目录的 `data/`
里有 `alerts.json`（方式 B 构建后需要手动复制，见安装一节）。

**打开页面没有出现浪高徽章？**
依次检查：①这个页面在不在五个站点之内；②这个话题是否已被雷达
收录（数据里有才会有徽章）；③`data/topics.json` 是否存在且不是
空的；④刷新页面再试。若话题是最近才收录的，去设置页点「立即
从实例站点刷新数据」再刷新页面。

**点收波提示「无法读取当前页面」？**
`chrome://` 开头的浏览器内部页面、应用商店页面等受保护页面
读不到，这是 Chrome 的限制，在普通网页上重试即可。

**收波时选中文本没有被保存？**
先选中文字、再点扩展图标打开弹窗（打开弹窗后选区丢失就读不到）。
弹窗里若显示「已选中 N 字」即表示会一并保存。

**改了代码/换了数据，扩展没变化？**
去 `chrome://extensions/` 点扩展卡片上的刷新（↻）按钮；
只换数据文件时也需要刷新一次。

**回波箱的数据会丢吗？**
存在浏览器本地（`chrome.storage.local`），卸载扩展会被清掉；
重要回波请及时用「导出投波 / 下载 JSON」备份。

## 给开发者

本目录是扩展源码的正式存放地（引擎仓 `daiyanze/breaker-delta` 的
`apps/extension/`，monorepo 包名 `@breaker-delta/extension`）。
TypeScript（strict）源码在 `src/`：`logic.ts` 是纯逻辑（页面匹配、
角标计数、话题链接、收波记录、设置、预填 Issue 链接），
`popup.ts` / `content.ts` / `background.ts` / `options.ts` 是四个
入口。领域数据形状用 `@breaker-delta/core`
的类型，与站点发布器同一套，不手抄口径。

```bash
npm run build -w @breaker-delta/extension   # 构建到 dist/
npm test -w @breaker-delta/extension        # 跑 logic 测试
```

数据格式（回波记录、`topics.json`、`alerts.json` 的字段与匹配
规则）见英文主文档 [README.md](README.md) 的 Data formats 一节。
图标目前是简单的海浪占位图，正式版再换品牌图标。
